Phase 0 · Setup
// BEFORE WE WRITE ANY LOGIC

Install, log in, scaffold

Same five-command loop every Apify Actor starts with. Get here before the room splits into pairs.

  • Install the CLI. curl -fsSL https://apify.com/install-cli.sh | bash or brew install apify-cli. Verify with apify --version.
  • Log in. apify login — grab your token from console.apify.com/settings/integrations.
  • Scaffold the project. apify create claude-log-miner, pick a plain JS/TS template — no Crawlee needed, this Actor reads local files, it doesn't crawl the web.
  • Confirm the shape. You should have .actor/actor.json, src/main.js, and a Dockerfile in the folder.
curl -fsSL https://apify.com/install-cli.sh | bash
apify --version

apify login
apify create claude-log-miner
cd claude-log-miner
Phase 1 · Capture
// TURN A MESSY LOG INTO QUERYABLE DATA

Parse JSONL into a usage taxonomy

Almost nobody reads ~/.claude/projects/**/*.jsonl directly. The Actor does, and turns each session into a structured record: tool_use events, MCP server names, npm/pip packages, file extensions, keyword domains.

  • Read input. Actor.getInput() — take a glob path or a directory to scan for session files.
  • Stream + parse each line. Each JSONL line is one event; walk them and bucket by type (tool_use, MCP calls, imports referenced, domains touched).
  • Push one record per session. Actor.pushData() a structured taxonomy object per session file, not per line — keep the Dataset queryable.
  • Run it locally. apify run, then check ./storage/datasets/default for the output before pushing to the cloud.
import { Actor } from 'apify';

await Actor.init();
const { sessionsGlob } = await Actor.getInput();

// ...walk JSONL files, bucket events into a taxonomy...

await Actor.pushData({
  sessionId,
  tools: [...toolUseEvents],
  mcpServers: [...mcpNames],
  packages: [...importedPackages],
  domains: [...keywordDomains],
});
await Actor.exit();

apify run
apify push
Checkpoint
You should have a Dataset with one row per session before moving to gap analysis. If it's empty, check the glob path first — this is the most common stall point.
Phase 2 · Gap analysis
// FLOAT THE HIGHEST-VALUE GAPS TO THE TOP

Score against what you already own

Cross-reference the taxonomy against your installed skills and the plugin marketplace. An adjacency formula scores each candidate gap; a significance gate keeps a three-message session from firing a research run.

  • Load your installed set. Skills directory + plugin marketplace listing, as comparison data.
  • Score candidates. Adjacency: how close is this repeated pattern to something you don't have, weighted by frequency across sessions.
  • Apply the significance gate. Minimum session depth / repeat count before a candidate counts — this is what keeps the loop from becoming noise.
  • Rank and push. Output a ranked gap list to a second Dataset (or the same one, tagged type: gap).
SignalSourceWeight
Repeated tool_use with no matching skillCapture layerHigh
MCP server referenced but not connectedCapture layerHigh
Package imported once, never againCapture layerLow (filtered by gate)
Domain touched across 3+ sessionsCapture layerMedium
Phase 3 · Automate
// NO POLLING

Webhook on run success

Attach an ad-hoc webhook so ACTOR.RUN.SUCCEEDED fires with the run ID and dataset ID in the payload. Results get fetched the moment they exist.

  • Console → Integrations → Webhooks. Add an ad-hoc webhook scoped to this Actor, event ACTOR.RUN.SUCCEEDED.
  • Point it at a receiver. Any HTTPS endpoint — a Worker, a Zapier hook, whatever you've got live tonight.
  • Read the payload. runId + defaultDatasetId land in the POST body — no need to guess or poll for completion.
  • Fetch on event. GET /v2/datasets/{id}/items the instant the webhook fires.
curl "https://api.apify.com/v2/acts/USERNAME~claude-log-miner/runs/last/dataset/items?token=APIFY_TOKEN"

Phase 4 · Output
// MAKE IT REUSABLE, NOT ANOTHER TAB

Route findings into things that compound

A ranked gap list is only useful if it turns into something you'd actually act on. Route it into three shapes.

Vault notes

One markdown note per significant gap, dated, linkable — the raw research record.

Skill scaffolds

A stub SKILL.md for the highest-scored gap, ready to flesh out instead of starting from a blank file.

Plugin stubs

If the gap maps to a recurring MCP need, a minimal plugin scaffold instead of a one-off script.

The point
You leave with a working Actor in your own Apify account and a repeatable pattern for an agent that reads its own history and improves on it — not a one-time report.

Four ways to wire Apify into an agent

Same Actor, four different ways an agent can reach it. The right choice depends on how often the gap-check needs to run and how much context budget you're willing to spend keeping it warm.

PatternHow it firesContext costBest for
SkillsAgent decides to call it, on demandLow — loaded only when relevantAd-hoc "check my gaps now" asks
Cron prefetchScheduled Actor run, results cached ahead of timeLow at query time, cost paid upfrontDaily/weekly digest, no live wait
Webhook-triggered turnsACTOR.RUN.SUCCEEDED pushes a new agent turnMedium — a turn is spent per eventReacting the moment research finishes
Direct MCPActor exposed as a live MCP tool, called mid-conversationHighest — tool schema held in contextTight loops, iterative exploration
Rule of thumb
Push work to cron or a webhook whenever the result doesn't need to be decided on live — that's context budget you get back for the parts of the conversation that actually need it.
